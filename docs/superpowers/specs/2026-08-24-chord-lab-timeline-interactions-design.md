# MuseEcho 和弦实验室与可缩放结构地图设计

状态：视觉方案与书面规格已批准，进入实施

日期：2026-08-24

## 1. 目标

在不修改后端分析模型、不重新请求分析结果、不创建第二个歌曲音频实例的前提下，完成两项前端升级：

1. 将和弦详情升级为可交互的“和弦实验室”，以轨道动画展示组成音，并提供点击试听、科普详情和可靠的返回路径。
2. 将结构地图升级为类似录音文件的可缩放时间画布，使波形、歌曲段落、和弦、动态强弱、事件、选区和播放头始终共享同一时间坐标。

桌面端在结构地图下方展开大型详情面板；手机和平板端使用全屏三级详情。视觉继续遵守 `DESIGN.md` 的浅色莫兰迪、Warm Editorial、克制动效和真实性要求。

## 2. 范围与非目标

### 本次范围

- 响应式和弦实验室与返回交互。
- 组成音轨道、悬停解释、点击试听、钢琴按键反馈。
- 简洁的“构成 / 听感 / 情境”通用乐理区。
- 结构地图横向缩放与播放头锚定。
- 波形、段落、和弦、动态强弱和事件轨道同步缩放。
- 播放头经过和弦或事件时的聚焦提示。
- 移动端全屏详情、焦点管理和状态重置。
- 单元、组件、响应式和端到端验证。

### 非目标

- 不修改分析 API、模型、任务编排、上传或音频解码逻辑。
- 不推断后端没有提供的主歌、副歌、鼓组进入、主唱叠加等语义。
- 不通过 URL 参数保存选中和弦、组成音或缩放倍率。
- 不为试听新增 `<audio>` 元素或网络音频资源。
- 不在本阶段生成结合全曲调性的和弦功能、张力去向或上下文情绪结论。

## 3. 已批准的交互架构

`AnalysisWorkspace` 继续拥有分析结果、唯一 `TimelineController`、当前工作区视图、选中和弦和详情开关。歌曲播放仍由现有 `AudioPlayer` 与其唯一 `<audio>` 元素负责。

和弦实验室是结果工作区内的三级详情，而不是新路由：

- 桌面端：`Timeline` 保持完整宽度，详情在结构地图下方展开并允许页面继续向下延伸。
- 手机和平板端：详情通过 portal 呈现为全屏模态页，背景工作区 `inert`，返回后恢复触发按钮焦点。
- 响应式职责使用两个明确断点：现有 `MOBILE_WORKSPACE_QUERY`（最大 599px）继续控制手机专用和弦列表；新增最大 1023px 的详情页查询控制手机和平板全屏详情。1024px 及以上使用桌面内联详情。
- 切换歌曲分析结果时，依靠现有 `LoadedWorkspace` key 清空所有详情状态。
- 关闭和重新打开详情时保留时间轴上的和弦高亮，但清空组成音点击记录、钢琴按键动画和组成音解释，重新显示“选择一个组成音”。

不创建额外查询，不改变 `analysisId`，不重新挂载 `AudioPlayer`。

## 4. 组件边界

### `AnalysisWorkspace`

- 保留数据加载、结果视图切换、详情打开/关闭、移动端 portal、焦点陷阱和单音频所有权。
- 桌面详情布局由“侧栏”改为结构地图下方的大面板。
- 详情关闭只结束当前详情会话；时间轴选中和弦仍可用于恢复焦点和高亮。

### `Timeline`

- 保留现有真实波形、段落、和弦、能量和事件数据读取。
- 增加缩放工具栏、横向滚动视窗、统一虚拟画布和播放头聚焦状态。
- 保持片段选择、键盘播放位置控制和移动端和弦列表替代路径。
- 必要时将轨道渲染拆成文件内小组件；不把每条简单轨道过度拆成公共组件。

### `useTimelineViewport`

新增只负责视图几何的前端 hook，与 `useTimeline` 的播放状态分离：

- 保存 `zoom`，范围 `1–4`，步长 `0.25`。
- 根据视窗宽度和倍率计算时间画布宽度。
- 缩放后以当前播放头为锚点调整 `scrollLeft`。
- 提供时间与画布坐标换算，处理无效宽度和零时长。

### `ChordDetails` / `ChordOrbit`

- `ChordDetails` 继续处理置信度、unknown 和缺失 theory 的真实性分支，并承载标题、时间、置信度和通用乐理区。
- `ChordOrbit` 只接收已验证的 `pitch_classes` 和 `intervals`，负责轨道、悬停浮层、组成音选择和钢琴键视觉反馈。
- 试听逻辑放入小型 `useToneAudition` hook，便于隔离 Web Audio 生命周期和失败状态。

## 5. 结构地图坐标与缩放

结构地图由一个横向滚动视窗和一个统一时间画布组成。左侧轨道名称保持固定；右侧内容区域按同一倍率放大。

统一坐标公式：

```text
ratio = clamp(seconds / duration, 0, 1)
x = contentLeft + ratio * contentWidth
```

波形线段、段落边界、和弦区间、动态曲线、事件标记、选区和播放头全部使用同一 `contentWidth`。禁止各轨道分别计算宽度或单独缩放。

缩放行为：

1. 用户拖动“时间轴缩放”滑杆。
2. 统一画布宽度更新为 `viewportWidth × zoom`，同时尊重最小可用宽度。
3. 布局稳定后，根据 `currentTime / duration` 计算播放头新位置。
4. 更新 `scrollLeft`，尽量让播放头保持在视窗中央；靠近歌曲首尾时自然钳制。
5. 播放、seek 和选区继续使用真实秒数，不因缩放改变。

缩放不会重新采样或伪造后端数据。SVG 波形和动态曲线仅改变显示宽度，原始数组保持不变。

## 6. 轨道内容规则

### 波形

- 使用 `track.summary.waveform.minimums/maximums`。
- 缺失时保留轨道并显示“暂无波形摘要”，不使用演示波形替代。

### 歌曲段落

- 保留后端 `SectionResult` 的真实起止时间并显示为大区块。
- 若后端标签属于明确的语义标签（如 `intro`、`verse`、`chorus`、`bridge`、`outro`），前端可进行固定中文映射。
- 若后端只给出 `A/B/C`，显示“段落 A / 段落 B / 段落 C”，不推断为主歌或副歌。
- 点击大区块仍执行精确 seek 和选区。

### 和弦

- 继续应用现有可见性和置信度策略。
- 桌面轨道上的和弦可点击；移动端同时保留无重叠的时间顺序列表。
- 当前播放时间落入和弦区间时，节点轻微放大并出现简要提示。

### 动态强弱

- 使用 `time_series.kind === "energy"` 的真实点列。
- 与波形共用相同画布宽度和缩放倍率。
- 缺失时显示“暂无动态曲线”。

### 事件

- 当前后端只提供 `energy_changes`，因此正式文案限定为“动态上升/下降 + 时间 + 可用强度信息”。
- 播放头接近事件时间时，标记轻微放大并显示可读摘要。
- “鼓组进入、和声叠加、主歌回归”等效果稿文字属于明确的演示内容，不进入真实结果页，直到后端提供相应事件类型。

## 7. 和弦实验室交互

### 轨道与命中

- 每个组成音位于独立圆形轨道上，按钮圆心始终与轨道线重合。
- 三条轨道使用不同初始相位和较慢速度，避免元素初始重叠。
- 轨道装饰层 `pointer-events: none`，只有组成音按钮 `pointer-events: auto`，防止透明轨道拦截点击。
- 浮层通过不受圆形容器裁剪的定位层呈现，并钳制在视窗内。

### 悬停、焦点和点击

- 鼠标悬停或键盘聚焦：暂停全部轨道，当前组成音变色并放大，显示简短解释。
- 鼠标移开或焦点离开：隐藏浮层并恢复旋转。
- 点击或键盘激活：播放一次单音、更新下方组成音详情和钢琴按键动画；不要求旋转永久暂停。
- 连续点击 C、E、G 必须可独立切换，不允许前一个选中层遮挡后续按钮。

### 试听

- 试听由 Web Audio 在用户手势内生成约 1.2 秒的钢琴式衰减单音。
- 只在点击或键盘激活时发声，不在悬停、进入页面或页面切换时自动播放。
- 支持升降音名到频率的确定性映射；无法映射时禁用该音的试听，但解释仍可阅读。
- 关闭详情时停止仍在发声的节点并释放 `AudioContext`。

### 文案

- 组成音详情使用“音程距离 / 听感提示 / 记忆方法”等前端科普表达。
- 下方标题限定为“构成 / 听感 / 情境”，文本保持简短。
- 区域标题使用“通用乐理”，表明它是教学知识，不冒充歌曲分析事实；不显示算法名、quality、来源行或后端扩展说明。
- 无可靠 theory 时不展示轨道、情感或情境推断，只显示“暂无可用的和声细节”。

## 8. 状态、返回与焦点

详情会话内部状态包括 `selectedPitchClass`、试听状态、浮层状态和按键动画。它们不得提升到 URL、查询缓存或歌曲级状态。

关闭详情时：

- 卸载或重置全部详情会话状态。
- 停止试听并隐藏浮层。
- 手机和平板移除背景 `inert` 和 body 锁定。
- 恢复触发和弦按钮焦点。

重新进入时：

- 标题显示“选择一个组成音”。
- 没有 `.selected` 组成音。
- 没有处于按下状态的钢琴键。
- 轨道从预设错相位置开始缓慢旋转。

## 9. 降级、异常与无障碍

- `prefers-reduced-motion`：轨道保持静止；所有解释、选择和试听功能仍可使用。
- Web Audio 不可用或启动失败：显示轻量内联状态“此设备暂不支持试听”，不影响其他详情。
- 零时长或非法时长：缩放和 seek 控件禁用，所有坐标钳制到起点。
- 空波形、空能量、空事件、空段落分别显示真实空状态，不互相替代。
- 浮层内容同时可通过键盘焦点获取；移动端不依赖 hover。
- 所有按钮具有可见焦点；颜色不是选中、置信度或事件状态的唯一编码。
- 详情页保持现有 modal 语义、焦点陷阱、返回焦点和 Escape/返回路径。

## 10. 后端缺口记录

本次不实现下列后端工作：

- 将 A/B/C 结构段可靠分类为前奏、主歌、预副歌、副歌、桥段和尾奏。
- 识别鼓组进入、主唱叠加、乐器变化、旋律回归等语义事件。
- 结合全曲调性和前后和弦判断级数、功能、张力去向和上下文情感。
- 为和弦解释生成经证据约束的更长文本。

前端只为这些未来字段预留呈现位置，不建立猜测性映射。

## 11. 测试设计

### 单元与组件测试

- `useTimelineViewport`：倍率钳制、画布宽度、时间坐标、播放头锚定、首尾边界和零时长。
- `Timeline`：五条真实数据轨道仍存在；缩放状态统一作用于同一画布；波形与能量数据不被重采样；段落语义映射和 A/B 回退；事件摘要不虚构语义。
- `Timeline`：播放头进入和弦区间或接近事件时切换聚焦状态；键盘和触摸替代路径仍可用。
- `ChordOrbit`：C → E → G 连续激活；装饰轨道不接收指针；悬停/焦点暂停与离开恢复；浮层可见；钢琴键反馈同步。
- `ChordDetails`：unknown、低置信度、缺失 theory 和无法映射音名的降级。
- `AnalysisWorkspace`：桌面下方面板；手机/平板全屏 portal；返回后组成音状态为空；焦点恢复；结果加载次数保持一次；DOM 中仍只有一个歌曲 `<audio>`。
- `AnalysisWorkspace`：分别覆盖 599px、600px、1023px 和 1024px 边界，避免手机列表断点与全屏详情断点相互污染。

所有行为修改遵循先写失败测试、再实现的 TDD 顺序。

### 浏览器与 E2E

- 桌面：结构地图五轨同宽，2.20× 后同步变宽并锚定播放头；可横向滚动到歌曲首尾。
- 手机和平板：结构地图缩放无页面级横向溢出；和弦详情全屏；返回后重新进入为空白状态。
- 和弦实验室：鼠标与键盘都能连续选择三个组成音；悬停浮层不被裁剪；点击才发声。
- 动效：普通模式可见，`prefers-reduced-motion` 下静止。
- 回归：真实上传、分析结果加载、音频播放、删除和现有 PWA 流程不受影响。

## 12. 验收标准

1. 桌面详情位于结构地图下方；手机和平板详情为可返回的全屏页。
2. 页面始终只有一个歌曲音频元素，打开详情不重新获取分析结果。
3. 波形、段落、和弦、动态强弱、事件、选区和播放头同步缩放并保持时间对齐。
4. 段落与事件只显示后端可证实的语义，演示文案不进入真实结果。
5. 三个组成音可连续点击，悬停浮层不被裁剪，点击才试听。
6. 返回再进入时组成音选择、钢琴按键动画和解释全部为空白。
7. unknown、低置信度、缺失数据、无音频能力和 reduced motion 均有明确降级。
8. 定向测试、全量前端测试、类型检查、构建和独立 Docker E2E 全部通过。
