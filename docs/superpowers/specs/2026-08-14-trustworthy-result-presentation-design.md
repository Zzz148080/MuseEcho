# 可信结果页呈现设计

## 目标

以现有 MuseEcho 结果页的排版、播放器/Music DNA 双栏、结构地图五轨与选区控件为视觉和交互基线；移除不能代表音乐事实的内部标签和面向开发的提示，使用户能回听、定位、理解可靠的局部线索。

## 已确认的呈现边界

- 保留现有“结构地图”轨道渲染：选区、波形、段落、和弦、能量、事件、播放位置与选区控件的空间关系和视觉样式不改变。
- 不展示片段问答、文本事件列表、数据生命周期、任务编号、实时状态、算法版本、来源代码名或“后端真实阶段”等内部信息。
- 不将结构聚类标签 A、B、… 当作音乐段落显示。当整首结构不能形成少量稳定组时，段落轨道显示简短的“未形成稳定段落”状态，不显示内部编号。
- 不显示 `unknown` 和弦块。只显示达到既有可用置信度阈值的已持久化局部三和弦候选。
- 调性低于既有阈值时，Music DNA 显示“暂未判定”，不展示候选调名或置信度数字。
- 和弦详情保留选中候选的时间范围、名称、组成音和基本乐理释义；不展示算法版本、数据库持久化、前端补全等实现措辞。
- 基础乐理说明只服务于读图：A–G 为音名，`#` 为升半音，`m` 为小三和弦；不在页面中解释系统失败或辩护实现。
- 选区仍可通过地图拖动、播放位置和起止滑杆选择任意片段；其用途提示为“选择片段以回听和比较”。本迭代不增加按选区重新推断和弦的功能。

## 内容层级

1. 页头和已完成分析状态：保留；仅保留对用户有用的保留期限与真实上传来源。
2. 播放器与 Music DNA：保留时长、节奏估计、调性状态、可靠拍点和能量；移除“和声/结构数量”汇总，避免把少数局部候选放大为全曲结论。
3. 结构地图：保留原有五轨形态。段落和和弦轨道在无可信可视事件时显示空状态；波形、能量、事件和选区仍可操作。
4. 和弦详情：仅当用户点击可信候选时显示；默认显示短引导“选择地图中的和声线索”。
5. 删除问答/解释面板；保留数据删除入口作为次级操作。

## 验证

- React 单元测试证明：内部段落标签和低置信/unknown 和弦都不会进入地图或文本列表；可信候选仍可定位播放器和展示乐理；问答不在工作区渲染。
- 实际结果页以本次“江南烟雨”分析复验：无 A/B/C 段落字母和 unknown 和弦块；存在的 A# 仅作为可点击局部候选；选区和播放位置继续可用。
- 现有音乐分析算法和 API 数据模型不扩大，不伪造调性、段落或任意选区和弦结论。
