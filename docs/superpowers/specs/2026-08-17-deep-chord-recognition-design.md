# MuseEcho 第二阶段：深度学习和弦识别规格

日期：2026-08-17

状态：已由用户于 2026-08-18 书面批准；本文不表示模型、数据、训练结果或部署已经完成

实施计划：`docs/superpowers/plans/2026-08-17-deep-chord-recognition.md`

## 1. 目标

第二阶段把 MuseEcho 的和弦识别从仅支持 24 个大小三和弦的模板系统，升级为可训练、可评测、可复现和可在现有单机环境部署的专用深度学习系统。

本阶段必须同时实现四个结果：

1. 在独立真实音乐测试集上，显著优于当前 `chroma-triad-viterbi-v1` 基线；
2. 支持常见七和弦、减和弦和挂留和弦，而不把所有复杂和声强行归为大小三和弦；
3. 保留时间对齐、置信度、`unknown`、算法版本和 Evidence-first 边界；
4. 模型能导出为离线推理制品，并在 2 vCPU、4 GB RAM 的现有部署目标内运行。

本阶段的成功标准不是“训练 loss 下降”或“展示若干识别正确的歌曲”，而是锁定测试集、统一指标、可复现实验和完整线上回归同时通过。

## 2. 当前基线与问题定义

当前实现提取 22.05 kHz 音频的 STFT chroma，以 24 个大小三和弦模板计算相似度，使用固定门槛、调性弱先验和 Viterbi 平滑生成事件。它在合成大小三和弦上可重复、资源占用低，但存在以下结构性限制：

- 输出空间只有 12 个大三和弦、12 个小三和弦和 `unknown`；
- chroma 丢失音区、低音、部分泛音和音色上下文；
- 固定模板与阈值难以适配不同编配、混音、失真和现场录音；
- 当前合成测试不能代表真实商业录音的泛化能力；
- 前端、乐理、Evidence 和测试均把三和弦语法当作契约。

第二阶段保留这套实现作为冻结基线和故障回退，不再以持续堆叠模板和人工阈值作为主要提升路线。

## 3. 范围

### 3.1 本阶段包含

- 数据集登记、授权边界、标签转换、去重和防泄漏切分；
- 传统基线在同一测试集上的正式测量；
- 可缓存的 CQT 类输入特征；
- 小型时序深度模型、训练器、评测器和实验记录；
- 置信度校准、`unknown` 门控、时序解码与事件合并；
- ONNX 导出、数值一致性、CPU 性能和内存验证；
- 线上识别器接口、模型制品校验、回退路径和算法版本；
- 新和弦词表对应的 API、存储、前端和确定性乐理兼容；
- 模型卡、数据卡、复现实验说明和比赛展示材料所需的真实对比数据。

### 3.2 本阶段不包含

- 自动抓取或提交未经授权的商业音乐；
- 声源分离、旋律转录、乐器识别或端到端音乐理解大模型；
- 在线训练、用户音频自动回流训练或把用户音频发送给第三方；
- 依赖外网的生产推理；
- 为追求词表规模而支持数据极少的长尾爵士记号；
- 用 LLM 生成或修正和弦标签；
- 以人工挑选歌曲、训练集成绩或未锁定的验证集成绩作为最终验收。

## 4. 标签与输出合同

### 4.1 内部规范表示

模型和数据管线不得只传递不透明字符串。规范标签至少包含：

```text
root: C | C# | ... | B | N | X
quality: maj | min | 7 | maj7 | min7 | dim | hdim7 | sus2 | sus4 | N | X
bass: 1 | b2 | 2 | b3 | 3 | 4 | b5 | 5 | b6 | 6 | b7 | 7 | N | X
display_symbol: Cmaj7/E
```

其中：

- `N` 表示当前帧没有可辨认和弦，例如静音或无和声段；
- `X` 表示存在和声但标签超出首发词表、原始标注不可解析或证据不足；
- 产品 API 可继续把 `N`、`X` 和低置信预测统一呈现为 `unknown`，训练与评测内部必须保留区别；
- 升降号采用统一规范音级，原始拼写保存在数据转换报告中，不用于制造重复类别；
- 转位信息通过 `bass` 保留。首发产品是否显示转位由独立门槛决定，不能影响根音和性质的基本输出。

### 4.2 首发识别词表

首个比赛候选模型必须训练和评测以下性质：

- `maj`
- `min`
- `7`
- `maj7`
- `min7`
- `dim`
- `hdim7`
- `sus2`
- `sus4`
- `N`
- `X`

`aug`、`dim7`、`6`、`min6`、`9`、`add9` 和 altered chords 暂映射为 `X`，除非训练清单证明某类别在相互独立的训练歌曲中具有足够覆盖，并通过书面词表变更。禁止只因合成数据容易生成就扩大正式词表。

### 4.3 模型输出

模型按固定时间帧输出：

- root logits；
- quality logits；
- bass logits；
- chord-boundary probability；
- 可选的辅助 key logits，仅用于训练正则，不得覆盖声学和弦预测。

线上事件输出保持：开始时间、结束时间、规范 symbol、置信度、算法版本和可选诊断摘要。诊断 logits 不进入公开 API、数据库 Evidence 或 LLM。

## 5. 数据规格

### 5.1 数据来源登记

每个数据源必须在本地数据清单中记录：

- 数据集名称、版本和来源 URL；
- 音频和标注的许可证或使用依据；
- 下载日期、文件哈希和转换器版本；
- 曲目、作品、艺术家和可能的 cover-group 标识；
- 原始标签数量、规范化后标签数量、丢弃原因和时长分布。

真实音乐音频默认不进入 Git、Docker 构建上下文或发行制品。仓库只保存适配器、许可说明、匿名统计、哈希清单和小型程序生成夹具。

### 5.2 切分与泄漏防护

- 数据划分单位必须是作品或 cover group，不能随机划分帧或片段；
- 同一歌曲的不同版本、现场版、混音版或 cover 不得跨训练、验证和测试集；
- 能获得艺术家信息时，额外生成 artist-disjoint 泛化测试；
- 测试集一旦冻结，其标注不得用于调参、阈值选择、数据增强选择或人工纠错；
- 每次训练必须记录数据清单哈希和切分哈希；
- 完成近重复音频指纹和元数据审计后，才能生成最终切分。

### 5.3 数据增强

训练集允许使用可追溯的在线或缓存增强：

- 整数半音移调，并同步变换 root 和 bass 标签；
- 增益、动态范围压缩、轻度 EQ、混响和受控背景噪声；
- 编解码器退化和声道混合；
- 小范围时间伸缩，仅在标签时间边界同步变换时使用。

验证集和测试集不得应用随机增强。增强必须有可关闭的配置和消融实验，禁止用标签不变但音乐语义已改变的增强。

### 5.4 真实黄金集、合成监督集与 A/B 路线门禁

数据集必须显式声明且只能属于以下一种训练角色：

- `real-gold`：真实演奏音频与人工或人工复核的时间对齐和弦标注；当前包括
  Winterreise、RWC-P 和 GuitarSet；
- `synthetic-supervised`：由 MIDI/符号序列渲染且有精确标签的音频；当前候选为
  IDMT-SMT-Chord-Sequences 和 Jazznet；
- `weak-label-validation`：主要用于验证 MIDI 到和弦弱标签转换，不直接进入正式分数；
  当前为 BabySlakh；
- `rejected`：许可、音频或监督标签任一项不足，不能进入训练。WaivOps Lo-Fi Chords
  的 JSON 不含和弦名或时间边界，属于此类。

路线选择以下载校验、逐音频头时长求和和标签抽检后的数字为准：

- **方案 A（默认）**：当可用 `synthetic-supervised` 音频少于 60.0 小时，先用真实黄金集
  建立 CRNN 基线；合成数据只作为辅助采样和消融，不改变真实数据门禁；
- **方案 B（达到门槛时启用）**：当去重后可用 `synthetic-supervised` 音频达到 60.0 小时，
  执行“合成监督预训练 → 真实黄金集微调”。合成数据不得进入 calibration、validation
  或 test，也不得计入真实黄金 G1 的作品数和时长。

IDMT 必须按官方 triplet 及其底层和弦序列分组；Jazznet 必须按底层 progression/template
分组；GuitarSet 的 360 段必须按 30 个 lead-sheet 身份分组。任何一项分组元数据无法恢复时，
对应数据只能用于 smoke，不能进入正式预训练。

2026-08-18 全量审计已冻结方案 A：IDMT 的 7,500 轨提供 27.269370 小时可用标注，
Jazznet 的 11,401 轨提供 14.218611 小时可用标注，合计 41.487981 小时，低于 60.0 小时
门槛。IDMT 的 triplet/相同底层序列并集形成 2,026 个分组；Jazznet 形成 1,739 个
progression/chord template 分组。两者只作方案 A 的辅助采样和消融。

## 6. 特征与模型架构

### 6.1 输入

- 解码为有限、单声道、22,050 Hz PCM；
- 主输入采用 log-CQT 或 harmonic-CQT，保留至少 6 个八度和每半音多个频率 bin；
- 另保留低频分支或 bass-CQT，以支持转位和根音判断；
- 特征按训练集统计量归一化；
- 长音频按带上下文的块处理，输出必须裁剪重叠区并保持全曲时间连续；
- 特征配置、实现版本和统计量哈希是模型制品的一部分。

### 6.2 首个可训练架构

首个正式基线采用小型多任务 CRNN：

```text
log-CQT / bass-CQT
        │
        ▼
2D CNN encoder + normalization + dropout
        │
        ▼
双向 GRU 或等价轻量时序编码器
        │
        ├── root head
        ├── quality head
        ├── bass head
        └── boundary head
```

选择 CRNN 是为了先建立强、可部署和可消融的深度基线。Transformer/Conformer 只能作为后续对照实验，不能在没有基线、性能预算和消融证据时替换首个实现。

### 6.3 损失函数

总损失由以下部分加权组成：

- root 分类损失；
- quality 分类损失；
- bass 分类损失，只在标签有效时计算；
- boundary 二分类损失；
- 可选时序平滑正则；
- 类别权重或 focal loss，用训练集统计确定，不能读取测试集分布。

所有损失权重必须进入配置和实验记录。`N`、`X` 与稀有类别的采样策略必须单独报告。

## 7. 训练与实验合同

每次正式训练必须保存：

- Git commit、数据清单哈希、切分哈希和配置文件；
- Python、CUDA、框架与驱动版本；
- 随机种子和确定性设置；
- 训练/验证曲线、最佳 checkpoint 选择规则和停止原因；
- 各词表指标、混淆矩阵、置信度校准图和推理性能；
- 模型权重哈希、导出制品哈希和许可证信息。

模型选择只能使用验证集。测试集只在候选模型冻结后运行；同一实验周期不得反复根据测试集结果修改模型。若测试集被用于决策，必须将其降级为验证集并冻结新的测试集。

启用方案 B 时，训练阶段固定为：

1. `B0 synthetic pretrain`：仅使用 synthetic train，学习 root/quality/bass/boundary；
2. `B1 real-gold finetune`：恢复 B0 encoder，以较小学习率在 real train 上完整微调；
3. `B2 calibration and selection`：只读 real calibration/validation，拟合温度并选择候选；
4. `B3 frozen test`：checkpoint、阈值和 manifest 冻结后，只运行一次 real test。

B0 与 B1 必须分别保存优化器、数据清单和指标，不得把两阶段曲线拼接成一次训练；同时保留
“相同 real train、随机初始化”的方案 A 对照，以证明合成预训练是否真正改善真实音乐泛化。

## 8. 后处理和置信度

深度模型输出帧级概率，事件生成继续使用可测试的确定性后处理：

1. 温度缩放或等价方法在独立校准集上校准概率；
2. 组合 root、quality 和 bass 概率，并拒绝非法组合；
3. 使用 Viterbi、受限 CRF 或等价时序解码抑制抖动；
4. 边界 head 参与切分，但不能创建无声学支持的标签；
5. 短事件、静音、低能量和低置信结果映射为 `unknown`；
6. 合并相邻同标签事件，确保事件完整覆盖音频且不重叠。

置信度必须经过校准，不能直接把最大 softmax 当作可靠概率。公开已知和弦的阈值由“precision/coverage”曲线确定，并固定在模型 manifest 中。

## 9. 评测协议

### 9.1 指标

必须在同一冻结测试集上同时报告传统基线和候选模型：

- Weighted Chord Symbol Recall：root、maj/min、triads、sevenths、首发精确词表；
- 各 quality 的 precision、recall、F1 和 Macro-F1；
- `N` 与 `X` 的 precision、recall 和 F1；
- 边界 F1，容差固定并在报告中声明；
- 过分段和欠分段统计；
- Expected Calibration Error 和可靠性图；
- published-known precision、coverage 及其阈值；
- 按数据集、曲风、年代、艺术家独立性和音频质量分层的结果；
- 5 分钟音频的墙钟时间、峰值 RSS、模型大小和冷启动时间。

不得只报告总体 accuracy。所有时长指标必须按真实标注区间加权，并明确忽略区间和不可解析标签的处理方式。

### 9.2 比赛候选晋级门槛

在冻结测试集上，候选模型必须同时满足：

- 首发精确词表 WCSR 相对传统基线提升至少 8 个百分点；
- maj/min WCSR 不低于传统基线；
- 常见七和弦合并 Macro-F1 不低于 0.55；
- 发布为已知和弦的 precision 不低于 0.85，coverage 不低于 0.65；
- ECE 不高于 0.08；
- 相同输入、模型和配置的重复推理产生相同事件；
- ONNX 与训练框架的帧级最大绝对概率误差不高于 `1e-4`，最终事件完全一致；
- 在 2 vCPU/4 GB 基准环境中，5 分钟音频的和弦阶段不超过 30 秒、峰值 RSS 不超过 2 GB；
- 完整 MuseEcho 5 分钟分析继续满足 90 秒和 4 GB 总预算。

若真实基线测量证明某绝对门槛与数据难度明显不匹配，只能通过书面规格变更调整；不得在看到候选测试结果后静默降低门槛。

## 10. 线上集成

- 应用层依赖 `ChordRecognizer` 接口，不直接依赖 PyTorch 或具体网络类；
- `LegacyChordRecognizer` 封装当前实现；
- `OnnxChordRecognizer` 校验 manifest、模型哈希、特征版本和输出词表后才加载；
- 生产镜像不包含训练框架、训练集或 checkpoint 优化器状态；
- 推理不访问网络，不动态下载模型；
- 模型缺失、校验失败、加载失败或资源门失败时，任务使用 legacy 回退并记录稳定的非敏感算法来源；
- 任何回退都不能把 legacy 结果伪装成深度模型结果；
- 算法版本示例为 `chord-crnn-cqt-v2.0.0`，必须和模型 manifest 一致；
- pipeline version、Evidence、API 和 UI 必须接受新词表，同时保留旧结果可读性。

模型制品不得悄悄覆盖。更新必须通过新版本目录、SHA-256、模型卡和回归门禁完成。

## 11. 乐理与产品兼容

- 确定性乐理解析器扩展到首发词表，输出实际组成音数量、音程、性质和限制；
- 不能唯一解释的转位、等音或功能必须明确返回候选或限制，不伪造唯一答案；
- 前端解析器不能用只匹配 `m?` 的正则过滤新和弦；
- `ChordEvent.symbol` 仍保持短规范字符串，数据库字段长度在迁移前验证；
- `unknown` 不生成乐理详情，也不进入可供 LLM 使用的和弦 Evidence；
- 低置信新类别不得因为乐理引擎能够解析就自动变为可信事实。

## 12. 测试策略

### 12.1 数据和训练测试

- 标签解析、规范化、移调和 round-trip；
- 相同作品/cover/艺术家不跨切分；
- 数据清单哈希和许可字段完整；
- 特征时间轴与标注帧严格对齐；
- 随机增强同步更新标签；
- 固定小数据集 overfit 测试证明训练链能学习；
- checkpoint 恢复、早停和随机种子可复现。

### 12.2 模型和评测测试

- 每个 head 的形状、mask 和 loss 有限；
- `N`、`X`、无效 bass 和类别缺失不产生 NaN；
- 指标使用人工可验证的小例子固定；
- 重叠预测与整曲预测在有效区域一致；
- 校准、阈值和事件合并边界可重复；
- PyTorch/ONNX 数值和事件一致。

### 12.3 产品回归

- 旧三和弦结果仍可读取和展示；
- 新七和弦、减和弦、挂留和弦通过 API、数据库、Evidence 和 UI；
- 静音、噪声、损坏模型、缺失模型和超资源场景安全回退；
- 真实 HTTPS E2E 覆盖至少一个新词表和弦、一个 `unknown` 和一次 legacy 回退；
- 完整 Python、前端、类型、E2E、容器和安全门继续通过。


训练依赖与运行依赖分离。大 checkpoint、原始音频、特征缓存和本地实验日志必须被 Git 忽略。最终 ONNX 制品按发行策略打包，不因为体积方便而绕过哈希、许可证和漏洞审查。

## 14. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 数据许可不清晰 | 不能训练或发布模型 | 数据源逐项登记；不清晰的数据隔离，不进入正式候选 |
| cover 或片段泄漏 | 测试成绩虚高 | 作品级切分、指纹去重、冻结清单哈希 |
| 类别严重不平衡 | 模型只会大小三和弦 | 分层 head、类别统计、加权损失、Macro-F1 门槛 |
| 复杂和弦标注不一致 | 上限降低、训练不稳定 | 规范化映射、`X`、逐数据集报告、人工抽样复核 |
| 模型过大或过慢 | 现有部署无法运行 | 小型 CRNN 起步、分块推理、ONNX、量化和硬性能门 |
| softmax 过度自信 | 错误事实进入产品 | 独立校准集、precision/coverage 门、unknown 回退 |
| 新词表破坏系统契约 | API 或 UI 丢弃结果 | 先升级 parser/DTO/Evidence/乐理测试，再启用新模型 |
| 多轮训练污染测试集 | 无法证明泛化 | 验证集选模、候选冻结后只测一次、测试集降级规则 |
| 合成数据主导 | 真实音乐泛化差 | 只允许预训练；真实集微调、校准、选模和测试；保留无预训练对照 |

## 15. 完成定义

本阶段只有在以下证据全部存在时才可标记完成：

1. 数据卡列出所有正式数据、许可、清单哈希和泄漏审计；
2. legacy 基线和候选模型在同一冻结测试集上的完整报告可重放；
3. 候选达到第 9.2 节全部晋级门槛；
4. 训练配置、权重、ONNX、manifest 和模型卡相互绑定；
5. 线上加载、回退、API、乐理、Evidence、前端和 E2E 通过；
6. 2 vCPU/4 GB 性能与完整 5 分钟分析预算通过；
7. 无未经授权音频、训练缓存、密钥或隐私数据进入仓库和发行制品；
8. 文档明确报告失败实验、剩余限制和未支持词表，不以演示样例替代测试结果。
